# Chapter 20: Start small: one loop, one record, one rule

<!-- p: 20-01 | draft 2026-11-25 -->
If you've read this far, you may be thinking that this is all very well for someone with seven projects, a hub, two brokers and a cat. It didn't start like that. The first night run lasted less than an hour. Everything else in this book was added one piece at a time, each piece because the last one had shown a need for it. You can start the same way, this week, with three things: one record, one loop and one rule.

<!-- p: 20-02 | draft 2026-11-25 -->
The record comes first, because everything else depends on it. It's a place, outside any chat, where the truth about your work lives: what you want done, why, and where each piece stands. It can be a plain text file. It doesn't need to be clever. What matters is that it isn't the AI's memory, which you can't fully see, and it isn't a chat, which starts empty next time. Chapter 4 is the long version of why.
<!-- src: chapter 4 (agreed: the store; "is it stupid, or has nobody given it the right context?"; value hidden in memories the user can't see; context starts empty in each new chat, glossary) -->

<!-- p: 20-03 | draft 2026-11-25 -->
Start the record with a short list of things you'd like done. For each one, write a line on what it is, a line on why it matters, and a line on what finished looks like. That last line is the one people skip, and it's the one the AI needs most. "Tidy the photos" is a wish. "Every photo from October is in a folder named by shoot, and there are no duplicates" is something a machine can do, and check that it did.

<!-- p: 20-04 | draft 2026-11-25 -->
The loop comes second. A loop is a job that runs on a schedule without you, does one thing, and writes down what it did. Make your first one modest. It could read your record each evening, pick the top item that it can safely do alone, do it, and write a short report. Or it could do no building at all, and simply read the record each morning and tell you what's stuck. My first useful loop was exactly that: a morning brief that read the night's reports and wrote me one page.

<!-- p: 20-05 | draft 2026-11-25 -->
However small it is, set it up so that it proposes and you accept. If it writes code, its work goes on a pull request. If it writes anything else, it goes somewhere you'll look before it reaches anyone else. Then read every report it writes for the first week, all the way through. That's how you learn what it does when you're not watching, and it's cheaper to learn it now than later.

<!-- p: 20-06 | draft 2026-11-25 -->
The rule comes third, and the best first rule is a "never". What must this never do? Never publish. Never spend money. Never touch these folders. Never put this person's name anywhere. Write it down in the place the loop reads before it starts work, not in a separate file it might never open. Chapter 10 is the story of what happens when a rule lives in the wrong place.

<!-- p: 20-07 | draft 2026-11-25 -->
Then let it run, and resist the urge to build more. A week is enough to show you a lot. Some nights it will do more than you expected. Some nights it will stop for a reason you'd never have guessed. Each time something goes wrong, fix the cause and write one line about what you changed. That line is your first lesson. When the same thing goes wrong twice, look at where that lesson lives, and move it somewhere the loop will read it.

<!-- p: 20-08 | draft 2026-11-25 -->
After a week or two, you'll know something no book can tell you: how much your loop actually gets done in a night. Write that down. It's your own pace, and it's worth more than any estimate. The AI will plan in a human team's weeks until you give it a better number. Chapter 3 is about that borrowed pace, and how much changed once we measured our own.
<!-- src: chapter 3, 03-10 (agreed: "we stopped borrowing a pace and made our own"); theme note 2026-11-21-theme-pace-anchoring ("measure your own pace, don't borrow one") -->

<!-- p: 20-09 | draft 2026-11-25 -->
Only then add the next piece, and only the one that hurts most. If you keep forgetting why you decided something, start writing decisions down. If the loop keeps running out of things it's allowed to do, write more items, or let it suggest some. If you find yourself checking ten places every morning, that's when a page that gathers everything starts to earn its keep. My Hub came about that way. It wasn't the first thing I built. It was the answer to having too many places to look.

<!-- p: 20-10 | draft 2026-11-25 -->
There are two things I'd avoid at the start. The first is building the big system first. A hub with nothing feeding it is just a nice page. The second is giving the loop every power on day one. Let it read before it writes, and write before it publishes. Each new power is a decision, and it should feel like one. Chapter 8 is how I handle the powers that matter, and chapter 14 is about why I still hold some of them back.

<!-- p: 20-11 | draft 2026-11-25 -->
You don't need my tools to do any of this. You need an AI that can run on a schedule, read and write files, and leave you a report. Several can, and by the time you read this there will be more. The particular product matters far less than the three pieces and the order you add them in. The appendix has a template for each one, ready to copy: a record, a night run, a lesson, and a never list.

<!-- p: 20-12 | draft 2026-11-27 -->
If a friend asked me tomorrow how to start, I'd tell them this. Pick one job that annoys you every week, and get an AI to do it with you. Build the system around it later. That's how it began for me. The firewall changes in chapter 1 were that job: they came round again and again, and each one took me hours. Writing down how they should be done was the first piece of all this, long before there was anything to call Jimmy.

<!-- p: 20-13 | draft 2026-11-25 -->
One record, one loop, one rule. It sounds like too little to matter. But each of them compounds. The record gets truer every night. The loop gets a little better with every lesson that's moved to where it's read. The rule list grows by one line each time something surprises you. That's the whole idea of this book, at the size of a single evening's set-up.
